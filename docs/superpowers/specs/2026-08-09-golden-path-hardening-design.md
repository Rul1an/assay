# Golden-Path Hardening Design

Date: 2026-08-09
Issue: [#2176](https://github.com/Rul1an/assay/issues/2176)
Base: `55e8103029583a16af96e1eafe73025192d69cd2`

## Goal

Harden the generated `assay-golden-path` project skill and the checks that keep
it reproducible before issue #2152 adds plugin packaging. The work is split so
gate durability lands before public wording or generated bytes change:

1. PR A makes the checks scheduled, non-destructive, checkout-stable, and
   mutation-proven.
2. PR B improves public discoverability, working-directory precision, and
   vocabulary after PR A protects those changes.

Neither PR changes Assay runtime behavior, MCP protocol behavior, command
results, or the nine-step journey.

## Current Measurements

On the base commit named above:

- `.github/workflows/kernel-matrix.yml` runs
  `pre-commit run --all-files --show-diff-on-failure` in job `lint`, but the
  skill validator checks only `pull_request.paths` and not that executor.
- `docs-generated-drift-self-test` is restricted to `stages: [pre-push]`.
  The workflow's plain `pre-commit run --all-files` therefore does not run it.
- The self-test trigger omits
  `scripts/docs/generate-agent-golden-path.py`, although the self-test mutates
  that generator.
- `scripts/ci/test-check-docs-generated-drift.sh` rewrites five tracked files
  and relies on an `EXIT` trap to restore them.
- `.claude/skills/assay-golden-path/OTHER.md` is not ignored by the current
  nested negation rules.
- Both shipped skill files are tracked, but neither has an `eol=lf` rule.
- `workflow_pull_request_paths()` rejects unsupported entries but does not
  give a distinct diagnostic for tab indentation and does not reject an
  active sibling `paths-ignore` key.
- `read_bounded_evidence()` checks `is_file()` before `is_symlink()`, so some
  symlinks can be reported as missing rather than as forbidden file types.
- The generator contains four `assert` statements that disappear under
  optimized Python.

## Shared Constraints

- Keep one writer per branch and use a separate worktree and target directory.
- Write each behavioral or mutation test first and record its named RED before
  the smallest GREEN change.
- Use one structural workflow reader for path scheduling and executor checks;
  do not implement the YAML rule twice.
- Keep all hostile or malformed inputs bounded before materialization.
- Run every mutation in disposable scratch state. A test process must not
  rewrite the repository under review, even temporarily.
- Bind measurements and reviews to the exact committed head SHA.
- Keep the generated skill ASCII-only and byte-identical at both destinations.
- Require final-head review quorum under `AGENTS.md`, including a read-only
  Claude Code Desktop review in the existing context-bearing review chat.

## PR A: Durability And Gate Execution

PR A is a prerequisite for #2152 step 4. It changes checks and repository
metadata, not the public journey text.

### 1. Schedule The Self-Test In CI

Update `.pre-commit-config.yaml` so `docs-generated-drift-self-test` participates
in the default pre-commit stage used by the workflow. Its file filter must also
include `scripts/docs/generate-agent-golden-path.py`.

The validator reads the bounded `.pre-commit-config.yaml` input and
structurally selects the unique active hook with id
`docs-generated-drift-self-test`. It requires that hook to be eligible for the
default pre-commit stage and that its active `files` expression covers the
generator. A commented or duplicate hook does not satisfy the rule.

The contract validator continues to require `.pre-commit-config.yaml` and the
owning workflow in `pull_request.paths`, and adds `.gitattributes` to that set,
so edits to any scheduling or byte-normalization surface cannot bypass the
head-side lint job. The contract hook's own `files` expression also includes
`.gitattributes`.

Required RED mutations:

- restore `stages: [pre-push]` and observe a scheduling assertion fail;
- remove the generator from the self-test filter and observe the named trigger
  assertion fail.

### 2. Pin The Workflow Executor

Extend `scripts/ci/test-agent-golden-path-skill.py` with a structural reader for
the active `jobs.lint` block. It must require:

- exactly one active `lint` job;
- no job-level or executor-step `if` condition;
- no truthy `continue-on-error` on the job or executor step;
- exactly one active executor step whose shell body contains the exact command
  `pre-commit run --all-files --show-diff-on-failure`;
- no additional pre-commit invocation or hook-stage override in that step.

Comments and commented jobs do not count. The reader will use indentation and
key structure already needed by `workflow_pull_request_paths()` rather than a
second approximate parser.

Required named mutations:

| Mutation | Required diagnostic class |
|---|---|
| Remove or comment out `lint` | missing active lint job |
| Remove or comment out the command | missing active pre-commit executor |
| Replace `--all-files` with `--files` | noncanonical executor command |
| Add `if: false` to job or step | gated executor |
| Add `continue-on-error: true` | fail-open executor |
| Add `--hook-stage pre-push` | noncanonical executor command |

### 3. Pin Tracking, Ignore Scope, And Line Endings

Narrow `.gitignore` with an inner directory wildcard so only
`.claude/skills/assay-golden-path/SKILL.md` is re-included. Add explicit
`text eol=lf` entries in `.gitattributes` for both shipped skill paths.

The validator will ask Git for repository state instead of reimplementing Git
ignore rules:

- `git ls-files --error-unmatch` must succeed for each shipped skill;
- `git check-ignore --no-index` must report
  `.claude/skills/assay-golden-path/OTHER.md` as ignored.

Scratch hardening cases must initialize a Git repository and index the expected
fixtures so these assertions exercise real tracking behavior. A line-ending
test reads the active repository attributes through `git check-attr eol` and
requires `lf` for both paths.

Required mutations independently untrack each skill, make the sibling visible,
and remove each `eol=lf` entry. Each must reach its named guard.

### 4. Make The Drift Self-Test Scratch-Only

Rewrite `scripts/ci/test-check-docs-generated-drift.sh` so its baseline and
every planted defect live under `mktemp -d`. The seeded scratch repository uses
the tracked working-tree inputs, then each case mutates only its own copy and
runs the copied gate from that scratch root. No backup-and-restore path remains.

The outer self-test snapshots the complete reviewable repository state before
and after the full mutation battery. The snapshot includes:

- index and worktree status, including untracked entries;
- path, type, and content or symlink-target digest for every tracked or
  non-ignored untracked working-tree entry outside `.git`.

Any difference is a failure. Because all writes are outside the repository,
SIGTERM or a failed assertion cannot leave a tracked file modified.

The script switches to `set -euo pipefail`; expected non-zero gate runs are
captured explicitly rather than relying on global error suppression.

### 5. Harden Workflow Parsing

The shared workflow reader fails before partial path extraction when it sees:

- tab indentation in the relevant `on.pull_request` or `jobs.lint` structure;
- an active `on.pull_request.paths-ignore` sibling;
- malformed list content under `paths`.

The diagnostics distinguish malformed indentation, mutually exclusive path
filters, and unsupported path entries. Mutations must assert those exact
classes so malformed YAML cannot masquerade as a mere missing-path failure.

### 6. Reject Symlinks Before File Checks

`read_bounded_evidence()` checks `is_symlink()` before `is_file()`. The named
diagnostic remains that skill evidence must be a regular tracked file.

Hardening tests independently replace the Codex and Claude skill with a
symlink. At least one symlink targets a regular file; an additional dangling or
directory target proves the check is about file type rather than target
existence.

### 7. Exercise Both Generator Destinations

The scratch drift self-test independently removes each entry from
`SKILL_OUTPUTS` in the copied generator. Each mutation must fail because the
corresponding fresh output was not produced. The test names the missing Codex
or Claude destination rather than asserting only a count.

### 8. Make Optimizer Safety Property-Wide

Replace the generator's four type-narrowing `assert` statements with explicit
typed validation helpers that fail under both normal and optimized Python.

The optimization gate parses both
`scripts/ci/test-agent-golden-path-skill.py` and
`scripts/docs/generate-agent-golden-path.py` with `ast` and rejects every
`ast.Assert`. It retains the existing `python3 -OO` invalid-schema mutation.
A new mutation inserts an `assert` as a mandatory guard and must fail the AST
gate before the optimized runtime can erase it.

### 9. Toolchain Disposition

Do not introduce a new Python launcher or a second version literal. The owning
workflow already selects Python 3.12 once and the repository's local hooks use
`python3`. There is no shared Python-version source for this slice to consume.
Creating one only for this gate would increase, not reduce, drift. The PR and
issue record this measured no-change disposition.

## PR B: Public Vocabulary And Generated Precision

PR B starts from merged PR A and changes the generated public artifacts once.

### 1. Canonical Discoverability

Add one generator-owned discovery block to
`docs/guides/agent-golden-path.md`. It names:

- the skill: `assay-golden-path`;
- the Codex path: `.agents/skills/assay-golden-path/SKILL.md`;
- the Claude Code path: `.claude/skills/assay-golden-path/SKILL.md`.

The block points to the generated skill instead of duplicating its journey.
The guide and generator use marker boundaries so removal, duplication, or a
hand edit is caught by the drift gate.

### 2. Precise Cursor Wording

Recheck current official Cursor documentation at implementation time and cite
the source and access date in the PR review packet. The public wording will
state only documented compatibility roots and the repository's own evidence:
Cursor documents `.agents/skills/` as a primary project root and
`.claude/skills/` as a compatibility root, while this repository does not
exercise Cursor runtime discovery. It must not claim runtime support.

### 3. Explicit Working Directories

Every step in the machine contract receives an explicit `working_directory`.
Eight steps use `.` and the protected-action step retains
`examples/privileged-action-gate`. The guide table and generated skill render
that field for every step. No renderer supplies an implicit default.

Tests mutate a default-root step and the protected-action step independently,
then require both machine and human views to fail on the same contract rule.

### 4. Semantic Public-Vocabulary Gate

Replace the exact-string-only forbidden tuple with a structural vocabulary
check over the generated skill:

- issue references are allowed only when they are derived from a contract
  `gap_issue` or an explicit contract non-claim;
- planning language such as roadmap ownership, future PR/slice, numbered
  implementation step ownership, and future plugin or marketplace packaging
  is forbidden after case, punctuation, and whitespace normalization;
- current behavior, commands, evidence limits, and explicit non-claims remain
  allowed.

Mutations use semantic variants rather than the original literals: alternate
case, punctuation, number words, and synonymous `next slice` or `future
marketplace` wording. Separate allow cases retain `[gap #216x]` links and the
contract's issue-owned non-claim.

### 5. Regenerate Once

Run the generator once after all source changes. Commit the contract, guide,
and both byte-identical skill outputs together. Record exact bytes and SHA-256
for both skill files on the committed PR head. PR A's LF and drift checks must
protect those measurements across supported checkouts.

Verification adds a read-only Codex skill-discovery run and a read-only Claude

what it discovered without claiming provider execution, external side effects,
or Cursor runtime behavior.

## Failure Policy

Every check fails closed. Missing Git, malformed workflow structure, unreadable
or oversized evidence, an unavailable generator, an untracked skill, or an
inconclusive mutation is a failure, not a warning or skipped proof. Diagnostics
identify the violated property and path without dumping unbounded or hostile
content.
