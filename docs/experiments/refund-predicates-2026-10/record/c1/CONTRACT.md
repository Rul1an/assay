# Synthetic C1 packet contract v0

Synthetic convention. Only C1 and scoped no-forbidden-dispatch interpretation; no workflow, provider, signature verification, C2/C3 or controls executed.

Closed top level: schema="refund.synthetic-c1.v0", case_id (nonempty ASCII identifier), source_class="synthetic_fixture", coverage="complete"|"incomplete", target_dispatch (identifier|null), approval {digest: 64 lowercase hex, action: object}, dispatch (null|{id:identifier, approval_digest:64 lowercase hex, action:object}). IDs match [A-Za-z0-9_.:-]{1,128}, no normalization. One packet scopes at most one dispatch. Coverage is fixture-declared over this synthetic scope, not established runtime coverage.

Protected action fields: merchant, payment_id, amount, exponent, currency, action. merchant/payment_id/action use identifier syntax; currency is three uppercase ASCII letters; amount integer 1..2^63-1, exponent integer 0..9 (bool forbidden). Approved action fixes currency EUR, exponent2, action refund; dispatch may have different well-formed values to permit comparisons. The approval action must have exactly the six protected fields and the stated EUR/exponent2/refund profile; any approval-side omission, extra field or profile deviation refuses input (exit2). The following missing/unknown rules apply only to dispatch.action. Unknown action fields are not silently discarded: C1 NOT_ESTABLISHED with reason unknown_action_fields. Missing action fields yield NOT_ESTABLISHED with reason missing_action_fields. Wrong field types/ranges, extra root/envelope fields, bad digest/IDs, duplicate keys/nonfinite/invalid JSON refuse input with exit2 and no stdout JSON. Bound input maximum1MiB, maximum container depth32 (root object depth1, each nested object/array adds1); invalid UTF-8, BOM, trailing data, parser recursion and nonfinite numbers anywhere refuse; no network.

Known dispatch: target_dispatch must equal dispatch.id and must be nonnull, else refuse inconsistent packet. C1 applicability=true; if protected fields missing or unknown => NOT_ESTABLISHED. Otherwise compare all six fields plus approval digest: all equal => ESTABLISHED, any mismatch => CONTRADICTED. Precedence is input validity, then dispatch unknown fields, then missing fields, then approval-digest mismatch, then protected-field mismatch, then match. Thus an extra or missing dispatch field plus a known mismatch is deliberately NOT_ESTABLISHED: this v0 refuses to interpret a partially understood action. This conservative choice preserves the merged scope and is not a general logic rule. Input validity is not issuer trust. The approval digest is an opaque fixture identifier; it is compared, never recomputed from approval content.
Missing dispatch but target_dispatch nonnull: applicability=true and NOT_ESTABLISHED/missing_dispatch_evidence (even if coverage complete). No target and no dispatch: applicability=false, result=null/no_recorded_dispatch; this does NOT establish absence.

Separate no_forbidden_dispatch: if a recorded dispatch C1 is CONTRADICTED => CONTRADICTED even with incomplete coverage; if known dispatch C1 NOT_ESTABLISHED or identified missing dispatch => NOT_ESTABLISHED. Otherwise complete coverage => ESTABLISHED, incomplete => NOT_ESTABLISHED. These are conditional on synthetic fixture declarations. All reports carry source_class and evidence_basis='fixture_declared'; never imply observed external effects.

Reader CLI: python3 reader.py PACKET. One JSON object stdout for semantic result, exit0 regardless of claim result. Invalid input exit2 stderr only. No output file overwrite surface in reader. Report keys schema='refund.c1-report.v0', case_id, packet_sha256 over exact input bytes, source_class, evidence_basis, c1 {applicable,result,reason}, no_forbidden_dispatch {result,reason}, non_claims. Consumer compares semantic projection c1/no_forbidden_dispatch, not source hashes, against independently fixed expectations. Closed C1 reasons: unknown_action_fields, missing_action_fields, missing_dispatch_evidence, no_recorded_dispatch, approval_mismatch, field_mismatch, exact_match. Closed no_forbidden_dispatch reasons: forbidden_dispatch, unresolved_dispatch, complete_fixture_scope, incomplete_coverage. Expectations include the reasons. non_claims is exactly ["no-live-execution", "no-runtime-coverage-proof", "no-issuer-authentication", "approval-digest-not-verified-against-content", "no-C2-or-C3", "no-adequacy-score"].

CA measures only reader.py; vectors are these evidence packets. trusted-local/process runner/JSON outcome; public observe_prefix stop_before='control'. A positive control is declared to satisfy CA manifest but remains unexecuted; no ordinary mutation, score, qualified control or resumability. Receipt raw streams retained outside measured tree. Wrapper refuses existing output and checks exact CA source inventory before importing a bounded export of pinned git objects. External dependencies unchanged.

CA accepted_exit_codes=[0], unproved_exit_codes=[2]. Only semantic fixtures in fixtures/ are CA vectors. Refusal fixtures in invalid/ are reader CLI tests, not semantic detections or CA baseline vectors.
