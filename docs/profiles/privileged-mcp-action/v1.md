# Privileged MCP Action Evidence Profile (v1)

- Profile id: `privileged-mcp-action/v1`
- Status: **experimental open profile** (not a standard)
- Conformance corpus: [`../../../conformance/privileged-mcp-action-v1/`](../../../conformance/privileged-mcp-action-v1)
- Sibling: [`v0.md`](v0.md) remains byte-exact and independently selectable

The key words MUST, MUST NOT, SHOULD, and MAY are to be interpreted as described in RFC 2119.

v1 is the denial-marker compatibility profile for the Assay application deny code
`-31999` (outside JSON-RPC `-32768..=-32000` and MCP's legacy/reserved partitions).
The current `assay-mcp-server` producer emits this v1 marker for Assay-originated
denials. The profile does not change policy or forwarding. Selection is **explicit**
(`assay evidence verify-privileged-mcp-action --profile-version v1`).
A bundle does not carry a profile id; autodetect is underdetermined when the only
profile record is `assay.enforcement_decision.v0`.

## What stays identical to v0

Stages 1–4, the claim matrix, report schema
`assay.privileged_mcp_action.verify.report.v0`, the four report non-claims, decision
and establish record constraints, fail-closed cardinality, and ADR-042 stop list are
the v0 rules. The `profile` member of the report records the **selected** profile
(`privileged-mcp-action/v1`), not a detected one.

## What v1 changes

**Optional observation schema** is `assay.denied_call_observation.v1`.

**Stage 3 marker triple** (all three MUST hold):

- `schema` is `assay.denied_call_observation.v1`
- `caller_visible_error.code` is the integer `-31999`
- `caller_visible_error.origin` is `"assay-proxy"`

A string `"-31999"`, a missing code, a wrong origin, or a cross-pair
(`v1` schema with `-32042`, or `v0` schema with `-31999`) is **not** a marker.
A well-formed observation that fails the triple is **valid and inert**.

A `assay.denied_call_observation.v0` payload under this profile is an unrecognized
in-namespace schema: **invalid**, fail closed. Mixed v0 and v1 observation records
in one bundle are invalid for the same reason. Absence of a denial observation on
a deny decision stays `caller_visible_denial: incomplete`; it MUST NOT become a
clean confirmation.

Marker binding, unbindable null digest, and ASSAY-W004 attribution use the same
shared classifier as v0. W004 recognizes either exact triple; the verifier
recognizes only the selected profile's triple.

## Non-claims

The four report non-claims are unchanged. Selecting or successfully verifying v1
does not prove producer identity, producer version, or migration history. The
profile does not claim MCP negotiation, policy or forwarding change, wire-origin
authentication, provider outcome, identity, compliance, or safety. Old Assay
binaries are not claimed to verify v1 evidence.
