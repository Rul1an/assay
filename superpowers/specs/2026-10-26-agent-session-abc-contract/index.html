It does not replace that design's acceptance criteria or authorize a capture, package projection, receiver experiment, production source adapter, or release. No schema, identifier, predicate, CLI output or exit-code contract changes.

    Views and common material¶

    All views concern this same capture. Do not run three agents or replay actions. Source availability is nested: A is a subset of B, B a subset of C.

    View Permitted source content Current gate
    A Original supported vendor events and hook occurrences, documented native inspection route, relevant capture settings Source attribution and byte-preserving packaging not yet established; keyed hook lifecycle reconciliation unavailable for this capture
    B A plus original proxy decisions, request receipts, session context and native stop; applicable policy/mode configuration and necessary proxy diagnostics Earlier proxy subset replay passes; B excludes supervisor and cannot reproduce full receipt closeout; combined A+B view not yet built or tested
    C B plus original kernel evidence and its capture/health provenance Blocked until pinned canonical archive verification and health/coverage eligibility pass

    Each view gets its own exact-membership manifest, externally selected expected digest, passive readers/instructions and source-specific provenance. Identical common material contains only scope, questions, bounds and integrity metadata. It must not disclose richer-view answers or B/C-only file names, counts and hashes to A: no shared supervisor summary containing B's stop/receipt verdicts, no shared kernel-health conclusions. Retain the full original supervisor privately. It contains C-only capture metadata and producer stop/receipt verdict summaries, so neither A nor B receives it, an excerpt, or a rewritten replacement. B may independently run native stop verification over its original stop, context and decision records. Full receipt closeout requires supervisor lifecycle inputs and is unavailable in B; the earlier packet-only replay does not transfer that result to B. C or the separate adjudicator may run the existing closeout method only with its original inputs and all dependencies satisfied. Producer verdict fields never substitute for recomputation; private adjudication never becomes a recipient's answer. The same leak boundary applies to mixed provenance.json: keep the original outside A/B, never relabel a filtered copy as original. Necessary source-local pins may appear as explicitly derived packaging metadata, without richer-view fields or verdicts. If the necessary provenance cannot be supplied within that boundary, stop packaging.

    Mandatory packaging gates and unavailable evidence¶

    Source/version attribution, exact-byte integrity and membership, bounded passive readers, credential screening and absence of richer-view leaks are mandatory for every packaged view. A failed or unavailable mandatory gate stops that view; B cannot proceed without an eligible A, and C cannot proceed without eligible B and kernel verification. No diagnostic label waives those gates.

    For this capture, vendor stream hook lifecycle events carry hook_id while raw hooks carry tool_use_id. The existing record_hook.reconcile requires native (hook_event_name, tool_use_id) keys. Its check is unavailable, not passed. Counts, order, timestamps, or IDs borrowed from assistant/user messages cannot fill the missing lifecycle keys. Keep all original identifiers and namespaces unchanged; do not inject a mapping or claim complete hook capture.

    This clarification permits only a future, separately authorized diagnostic view with that missing lifecycle evidence explicitly declared. It does not satisfy or relax the original design's lifecycle or full-acceptance requirements. Keep all six question rows: reported tool/input and the predeclared configuration-inspection decision may use eligible vendor bytes; proxy decisions may use B's eligible bytes. Hook completeness, native cross-source identity, and any proposition requiring the missing binding remain unavailable/unresolved. Host observations remain unavailable until C passes its gates. Offline reproducibility covers only the answers and methods actually available in that view. Missing evidence is neither a negative answer nor a failed vendor capability.

    native.stdout mixes runner and vendor material. Do not give A that entire stream or reserialize selected JSON as original bytes. Before packaging, freeze an explicit source-attribution rule tied to pinned vendor event shapes and exact runner output templates, exact ordered byte ranges, source digest and projection digest; account for every original byte exactly once (including runner framing) and require each range to match exactly one permitted source format without inferring from the expected answer. A JSON object with a type field alone is insufficient. Unknown, ambiguous or double-matching ranges stop packaging. Format consistency is not producer authentication or proof of atomic writes. Preserve the original stream outside recipient views. If this cannot be established, stop packaging and record the ambiguity. The complete range accounting and mixed-source digest remain with the adjudicator; each recipient receives only its eligible excerpts, their hashes and source-local navigation. Derived maps are navigation metadata, never new source events or identity evidence.

    Recipient runtime and disclosure boundary¶

    A recipient may be a human or a fresh model session. The model designated as the recipient is not an auxiliary model; it may inspect only its assigned view and the predeclared common instructions using the pinned passive reading route. No browsing, retrieval, connectors, auxiliary model calls or access to other views, prior answers, project history or the oracle is permitted. A fresh session alone does not prove this separation; verify the actual available tools, files and supplied context before dispatch. Account memory, personalization and project instructions or knowledge must be disabled or excluded from that context. Stop if this boundary cannot be established.

    For a model recipient, record the model/runtime and whether inference is local or hosted. A hosted inference channel is a separate disclosure to the named provider through the selected service/account, even when the recipient's tools have no network access. Authorizing that channel does not authorize general network access or retrieval. Record the owner's disclosure decision for the exact package, including retained account-usage metadata, paths and opaque values, before sending any package content. Keep that decision and any authentication material outside the recipient view; never reuse captured vendor credentials. A wholly local inference claim likewise requires evidence of the actual runtime.

    The future run's common scope instructions must state this same distinction, including how to read any frozen packet wording that says "no model/network". For a hosted recipient, question six's offline reproducibility means inspection with offline tools; it does not establish wholly offline inference. Do not silently change an archived instruction or its digest. Describe a hosted run as inspection with offline tools, not wholly offline inference or proof of provider-side isolation. These conditions admit no package, choose no recipient and authorize no disclosure or execution. B and C retain their separate gates; A/B/C execution remains HOLD.

    Frozen questions and answer rows¶

    Use these six original questions for every view. Record an answer, exact file/byte or existing-record reference, inspection method, admissibility limit, uncertainty and receiver friction. Separate unavailable evidence from evidence of a negative. Preserve canonical verifier states rather than inventing a new aggregate verdict or scalar trust score.

    Question Admissible basis Prohibited inference
    What tool/input did the runtime report? Original vendor record and exact reference Report equals execution; truncated argument equals exact input
    What decision did this proxy record? Decision bytes and applicable policy/mode Allow equals execution success; unknown mode equals enforcement
    Is the vendor call the same as this proxy call? Existing admitted native binding, uniqueness and window conditions Caller-supplied metadata, ordering or timestamps alone establish native identity
    Which host operations were retained? Positive verified kernel record with eligible provenance/health Missing event proves no activity; event proves per-tool causality
    Does a specific proposition contradict retained evidence? Existing predicate and its required binding/coverage Missing source alone proves contradiction; diagnostic relation becomes admitted predicate
    Can an offline receiver reproduce the answer? Exact package, pinned passive method, independent expected digest and fresh results Producer summary or process exit0 alone proves validation

    The request receipts support only the existing caller-asserted request-to-decision byte association. Keep event IDs, context IDs, receipt scope/sequence, typed RPC IDs and vendor IDs unchanged and in their existing namespaces. No injected ID, deduplication, timestamp backfill, cross-source identity or causal join is added. A unique receipt match does not answer the stronger native-identity question. closed and complete retain their existing limited meanings; neither is a whole-action verdict, authenticity, global completeness or durable-storage proof.

    Predeclared decision and bounded method¶

    The investigation decision is: for the reported policy_denied attempt, should an investigator inspect MCP policy configuration, vendor permission configuration, or leave the responsible layer unresolved? Each recipient must justify the choice from its own view. A may already contain the returned denial text and answer equally well; do not strip that legitimate vendor-visible information to manufacture B's advantage. B may establish that the proxy denied a request with particular bytes and reason code, but cannot thereby establish native vendor-call identity. If the chosen action requires that stronger binding, leave it unresolved. Native closure/accounting is a secondary evidence-quality question, not a value win merely because only B contains the proxy's files. C must justify an additional supported decision about positively retained host observations to warrant kernel integration. This technical value question does not establish customer demand or a USP.

    After separate authorization, prepare the views and gate each independently. Use fresh separate recipients without exposure to other views; the previous packet-only recipient has seen B material and is ineligible for A. If separate recipients are unavailable, use one fresh recipient sequentially A then B then C, freezing each answer file and its SHA256 first, and label the outcome a contaminated diagnostic comparison, not a blind study. Same six questions, instructions and 20-minute inspection ceiling per view; record actual commands/time/friction and no automatic retries. An exceeded budget is an unfinished inspection, not a source's negative answer. One bounded round only. Do not fill in the answer table while defining this contract.

    The oracle remains outside all views. Only a separate adjudicator may compare frozen answers with original fixture wire records afterward. Oracle evidence covers fixture-received frames, not vendor rejection, all task activity or execution success. Keep adjudication findings separate from recipient answers; never retroactively replace an answer or present oracle-assisted work as cold.

    Controls, limits and acceptance gates¶

    Before executing the comparison, pin exact view membership and all reader/source hashes; apply existing size/depth/occurrence ceilings before materialization. Keep original design limits (64 incident input occurrences, 256 MiB outer source bytes, 240 MiB declared occurrence bytes, and all nested limits). They are ceilings, not an admission claim for these experimental sources. No new production parser or schema is authorized by this document. Existing receiver limits remain effective.

    Each authorized offline control uses a disposable copy; originals stay unchanged:

    • Missing source and duplicate occurrence: retain unknown/unavailable or refusal; never merge duplicates into a supposedly unique call.
    • Foreign-session or valid identity swap: existing binding rules must refuse the affected claim; a hash match alone cannot admit it.
    • Byte corruption and semantically invalid input with recomputed manifest: distinguish integrity detection from canonical semantic refusal. Unsupported source semantics are unavailable, not a newly implemented validator.
    • Coherent source replacement: an independently pinned expected digest detects it; without an external expectation, record that authenticity is not established.
    • Apply existing hostile-input and output-preservation tests from the original design when a changed parser/projector makes them relevant; do not claim their coverage from this document or build another general harness.

    The current capture has no demonstrated parallel-identical or reused-ID control; positive file/process/network coverage still needs kernel verification. The original design's full acceptance therefore remains unmet. A diagnostic comparison may report bounded findings but cannot upgrade them to full acceptance. Synthetic controls cannot fill missing real controls. Any further capture needs new authorization and its own identity; it cannot be spliced into this run.

    Stop the affected view on unknown source/version, attribution ambiguity, ineligible health, missing canonical method for a claimed verification, mismatched provenance, leaking scope, absent control required for the diagnostic method, or exceeded resource bound. Only the explicitly unavailable evidence above may be reported as unavailable without blocking a diagnostic view; it never passes the corresponding full-acceptance gate. Mark C unavailable while its gate is unmet; do not substitute fixture/oracle events for kernel bytes. If A yields equally sufficient supported decisions, stop broader integration or justify only a portability adapter. If no supported incremental decision changes, do not productize the comparison. If identity/window conditions remain missing, stop strong joins. Any new predicate or stronger guarantee needs a separate compatibility decision/ADR, not a footnote here.
